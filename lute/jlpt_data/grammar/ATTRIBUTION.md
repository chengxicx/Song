# Grammar data attribution

## `n5.json` – `n1.json`

### jkindrix base (595 entries)

Verbatim copies of the curated JLPT grammar library from
**japanese-language-data** by Justin Kindrix and contributors:

- Source: https://github.com/jkindrix/japanese-language-data (`grammar-curated/`)
- License: **CC BY-SA 4.0** — https://creativecommons.org/licenses/by-sa/4.0/
- Counts as vendored: N5 77, N4 89, N3 130, N2 149, N1 150 (595 entries total)
- Fields used at runtime: `id`, `pattern`, `formation`, `meaning_en`,
  `examples[].japanese`.  The remaining fields (`meaning_detailed`,
  `examples[].english`, `formality`, `related`, …) are kept so the files stay
  verbatim copies.

### Merged study-material entries (715 entries, 2026-09-29 / 2026-09-30)

715 further entries were merged from structured transcriptions of nine
Chinese-market JLPT grammar study PDFs (private-material, private-material, N2 private-material, private-material, and private-material N1/N2/N3/N4/N5 grammar material+grammar material by
private-authors/private-authors, private-press 2014), transcribed into
`scripts/grammar_materials/n*.json` and
`scripts/grammar_materials/n{1,2,3}_materials.json`, merged by
`scripts/merge_grammar_materials.py`:

- Counts: N1 156, N2 186, N3 213, N4 96, N5 64 (the jkindrix 595 above are
  untouched)
- Each entry keeps its `id`, `pattern`, `level`, `meaning_en`,
  `meaning_detailed` (Chinese), `formation`, and `examples`
  (`japanese` + `chinese`, `english` left empty — the source PDFs have no
  English), with `examples[].source` naming the material file.
- These entries are a derivative of the CC BY-SA 4.0 data ecosystem and are
  distributed under **CC BY-SA 4.0** as well.

Entries whose construction jkindrix already carries (or that are bare
vocabulary) are listed in `_VOCAB_IDS` / `_DUPLICATE_IDS` inside
`lute/read/render/grammar_analysis_ja.py` and never fire; the merged
construction shapes that derivation cannot express (AつBつ, ば~ほど, ...)
live in `_CONSTRUCTION_RULES` in the same file.

These entries are matched by specs *derived at load time* from the
descriptive `pattern` text — see `_load_level()` in
`lute/read/render/grammar_analysis_ja.py` for the derivation and validation
rules.  Nothing in this directory is hand-tuned per entry.

## `zh.json`

Simplified-Chinese glosses for all 1310 entries above, keyed by the upstream
`id`.  Written for this project (Song), so the reading-page grammar panel can
describe points in Chinese; the glosses for the jkindrix 595 are a derivative
of the CC BY-SA 4.0 data above and are distributed under the same license.
Regenerated by `scripts/generate_grammar_zh.py --write` (the ZH dict in that
script is the single source of truth).

## `zh_enrichment.json`

Chinese wording for the 595 jkindrix entries' *enrichment* fields — the 接续
(`formation`) line, the 注意点 (`formation_notes` block) and the translation of
the curated 参考例句 — keyed by the upstream `id`:

```json
{"au-together": {"formation": "V ます词干 + 合う …",
                 "notes": "…",
                 "examples": {"問題について話し合いましょう。": "我们来讨论一下这个问题吧。"}}}
```

`zh.json` only localizes the description, so without this file the Chinese
panel printed the English prose the vendored rows carry ("Not yet: まだ + V
ていない …", "I haven't done my homework yet.").  Example translations are
keyed by the Japanese sentence rather than by index, so a reordering can never
mis-assign one; only entries that actually need it are present (the 715 merged
material entries already carry Chinese `formation` / `examples[].chinese`).

Regenerated by `scripts/enrich_grammar_zh.py --write`, from two inputs
recorded per row in `scripts/grammar_materials/zh_enrichment_sources.json`:

- **`formation` — the Chinese study materials above, 172 of 595 rows.**  A
  textbook's 接续 is the authoritative Chinese notation for the pattern, so
  the material's own words win where a material entry names the same point
  (both patterns must share the same longest Japanese fragment, so から never
  picks up からある).  The materials put a *meaning* list in that column for
  some rows (`1、表示推测；…`) and an OCR artifact for others
  (`用言?动词连体形`); those are rejected, or repaired, rather than shown on a
  接续 line.
- **`notes` — the translation, 566 of 595 rows.**  The materials' notes are
  mostly terse cross-references (`类似用法还有「ずくめ」`), while the vendored
  notes are usage warnings (`Do NOT use あげる for gifts TO you`) whose
  translation carries more.  A material note is taken only for the 29 rows
  where it actually names this row's own pattern — a note written for a
  neighbouring point is worse than either (`だけでなく`'s is about ひとり).
- **`examples` — the material's own translation where the two corpora share
  a sentence, which they almost never do (1 of 1787 sentences).**

The translation half is written for this project (Song) as a translation of
the CC BY-SA 4.0 source above and is distributed under the same license; the
material half is a derivative of the CC BY-SA 4.0 data ecosystem and is
distributed under CC BY-SA 4.0 as well.

# Korean grammar data

## `../grammar_ko.json` — base snapshot (404 entries)

A flat snapshot of **kimchi-grammar** (https://github.com/Alaanor/kimchi-grammar,
**CC BY 4.0** — https://creativecommons.org/licenses/by/4.0/), generated by
`lute/jlpt_data/generate_grammar_ko.py` from a local checkout of that project's
`point/*.yaml`.  Fields: `key`, `name`, `slug`, `meaning`, `type`, `examples`,
`focus`.  `focus` holds the literal phrases the Kimchi authors wrapped in
`<f>…</f>` inside each definition's examples — the Korean engine reuses them as
literal substring recognisers, so most entries need no hand-written rule.

## `../grammar_ko.json` — TOPIK level + Chinese/Korean glosses (all entries)

`lute/jlpt_data/enrich_grammar_ko.py` adds `level` (`TOPIK 1-2` / `TOPIK 3-4` /
`TOPIK 5-6`), a Simplified-Chinese `zh` and a Korean `ko` description to every
entry.  The lookup tables live in that script and are written for this project
(Song).

A kimchi `name` labels a whole family of senses, not one definition — three
rows are all called `(이)거니`, five are all `(으)오/소` — so a name-keyed lookup
handed every sense in a family the same description, wrong for at least one
member of most families (136 of the rows, 102 of which the reading page can
actually surface).  The script therefore looks up `_ZH_BY_KEY` / `_KO_BY_KEY`
**by record key first**, and the family-level tables are only a **fallback that
fills a gap**: they never replace a `zh` / `ko` / `level` a record already
carries, so a value from a better source (a book band, a book gloss) survives a
re-run.  That rule is what makes the script idempotent.

## `../grammar_ko.json` — 63 merged entries (`kgm_*` keys, 2026-09-29)

63 additional entries appended by `scripts/merge_grammar_ko_materials.py`, taken
from the **private-book** series (private-press Press) as reference
materials for study:

- *private-book to Early Intermediate* — private-authors,
  private-authors, private-authors
- *private-book* — private-authors, private-authors
- *private-book* — private-authors, private-authors

These three books are **scanned, copyrighted print works**.  What is stored here
is a small set of grammar-point names plus short example sentences transcribed
by OCR, used to close gaps in the CC BY 4.0 snapshot above; the `source` field on
each row records which book it came from.  The structured intermediate materials
(`scripts/grammar_materials_ko/*.json`) carry the same provenance.
No book text beyond short illustrative examples is reproduced, and the merged
rows are matched by specs **derived from the pattern text and validated against
each row's own examples** — see `_load_pattern_rules()` in
`lute/read/render/grammar_analysis_ko.py`.

The count grew in three steps: a first pass merged
40 rows, of which 3 were removed because the points they name are already in the
kimchi snapshot above under a different name (`A/V-거니와`, `V-지 그래요?`,
`V-되` — the materials files still list them, since they are genuine book pages);
then a bug in the coverage audit's containment test was found to be hiding real
gaps, and fixing it surfaced 26 more points plus one re-merge, taking the total
to 63.
