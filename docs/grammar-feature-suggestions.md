# Grammar feature suggestions

建议 5 项功能升级，全部建立在本轮已交付的语法库（595 → 650+ 条、N1–N5 全覆盖、
组合句型手写规则、中文释义补齐）之上，按投入/收益排序。每项标注所依赖的现有
机制与预估工作量，便于排期。

## 1. 语法库浏览页 `/grammar`

**形态**：独立页面（Flask route `@app.route("/grammar")` + 静态 JS），DataTables
按 级别 / 关键词 / 标签 检索 650+ 条语法条目；详情含完整例句（日文 + 中文 + 英文）、
接续（formation）、注意点（formation_notes）、重点/易考徽标（tags）。

**复用**：
- 数据：`lute/jlpt_data/grammar/n{n}.json` + `zh.json`（本轮已补齐，无缺项）
- 检索：项目里已有 DataTables 依赖（语言/书籍页在用），无需新前端库
- 例句朗读：复用现有 TTS（edge-tts）管线，给例句行加播放按钮即可
- 「书中例句」检索：对用户库跑一次分词 + 句子级 grep，列出该语法点在
  用户所读书籍中的真实出现位置（点击跳转阅读页）

**工作量**：1–2 天。风险低，纯只读页面，不碰阅读器核心。

## 2. 词条弹窗「本句语法点」

**形态**：点击生词弹出词窗时，对该词**所在句**跑一次语法引擎
（`lute/read/render/grammar_analysis_ja.py`，已有公开入口），在词形表单区
上方加一块「本句语法点」折叠区，列出命中的语法条目（点击展开释义）。

**复用**：引擎已支持按句子文本直接分析（`analyze_japanese(sentence)`），
词窗模板里插一行即可；同一句已在阅读页渲染时分析过的话可加一层
`session` 级缓存避免重复计算。

**工作量**：0.5–1 天。注意：只对 `ja` 语言的书启用。

## 3. 语法测验进 FSRS 复习队列

**形态**：例句挖空题——挖掉命中片段（引擎已返回 match span），4 选 1 干扰项
从「相似句型」中取（用 pattern 归一化后同接续槽位的条目做候选池）。

**关键约束**：`reviewcards` 表当前外键绑定 `words` 表，语法卡没有 word id。
两条路线：
- **A（推荐）**：新增 `grammar_reviewcards` 表（book_id / sentence / grammar_id /
  span / fsrs 字段），复习调度复用 FSRS 逻辑、UI 复用现有复习页模板；
- **B**：扩展现有 `reviewcards` 加 `grammar_id` 可空列 + 约束改造。

选 A 的理由：不动核心表结构，回滚容易；B 会牵连 status/同步逻辑。

**工作量**：3–5 天（含调度与 UI）。建议排在 1、2 之后。

## 4. 重点/易考标签筛选 + 掌握度追踪

**形态**：本轮材料已给条目打上 `tags`（重点 / 易考 / 易出题点）。浏览页与
复习队列支持按标签过滤；统计页按级别展示「已命中过 / 已复习 / 从未见过」
三个桶的覆盖进度条（数据直接来自语法分析的命中日志与 review 表）。

**工作量**：1 天（若 1、3 已落地则只是查询 + 展示）。

## 5. 与 ROADMAP 已有项衔接

- **LLM 语法追问（P3.1）**：词窗「本句语法点」（建议 2）命中为空时，把
  句子 + 已知词条喂给 LLM 生成一次性解释，并可「保存为自定义语法条目」
  进本地库（schema 与 `meaning_zh` 同构）。
- **i+1 例句生成**：以用户已掌握词汇为约束，为新学语法点生成例句
  （生词率 ≤ 1），生成结果写入浏览页的「AI 例句」区并与原例句并列。
- **每周测度 → 自动生成测验（P4.1）**：`measure_grammar_panel.py` 的语料
  统计已有「每个语法点的页面命中率」；把「命中率高但从未复习」的条目
  自动排进建议 3 的队列，即「从真实阅读中长出的复习计划」。

## 依赖关系

```
建议1(浏览页) ──► 建议4(标签/统计)
      │
      └──► 建议3(复习队列) ──► 建议5(自动生成测验)
建议2(词窗) ──────────────► 建议5(LLM追问)
```

本轮交付物（材料 JSON、审计报告、引擎手写规则、zh 释义、预览页）是以上
全部功能的数据与引擎底座；无需返工。
